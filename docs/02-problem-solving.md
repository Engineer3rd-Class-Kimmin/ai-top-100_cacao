# 문제를 어떻게 해석하고 풀었나

## FAQ보다 먼저 업무의 경계를 찾았다

처음에는 자료를 많이 모으면 답변 품질도 따라 올라갈 것이라고 생각했다. 실제로는 같은 문장이 문서마다 다르게 쓰여 있었고, 관계자가 아는 범위와 결정할 수 있는 범위도 달랐다. “누가 말했나”만으로는 부족했다. 직접 본 사실인지, 기록이 있는지, 지금도 적용되는지, 고객에게 공개해도 되는지까지 나눠야 했다.

관계자 인터뷰는 아래와 같이 담당 범위별로 활용했다. 이들은 대회가 제공한 가상 인물이다.

| 담당 영역 | 확인하려던 것 |
|---|---|
| 온라인 운영·CS·정산 | 주문·결제 대사, 환불, 구독, 영수증, 과거 약속 |
| 조합장 | 위임 권한, 승인·이관 경계, 예외 판단 |
| 생산자 | 작황, 방제, 로트 검사, 직접 관찰과 전언의 구분 |
| 교동 배송 담당·갯마을 운송 기사 | 송장·집하·인계, 대행 운행, 온도 이탈과 통지 |
| 수산물 공급 조합 | 조업·입고·냉동 재고, 인도 책임, 중량 기준 |
| 홍보 실무·외부 홍보 인물 | 광고 원본, 코드 조건, 실제 방송 발언과 정정 경로 |
| 체험 담당 | 운영 조건, 가예약, 인솔·보험, 현장 구매와 접수 |
| 실제 구매 경험을 가진 가상 고객 | 과거 처리 경험과 현행 규정의 차이 |

메시지는 200자 이내, 관계자별 질문 한도와 답변 대기 규칙을 고려했다. 답변을 직접 보내는 것은 사용자가 맡았고, AI 도구는 질문 작성·답변 정리·원본 분석을 도왔다. 자동 인터뷰 시스템을 만들어 전 관계자에게 일괄 전송한 것은 아니다.

## 사례 1. 정상이라는 마지막 기록만 믿지 않기

배송 인계 때 온도가 정상이라는 설명이 있었다. 그것만 읽으면 냉동 운송에 문제가 없었다고 답하기 쉬웠다. 하지만 기사 수첩과 인계 대장에는 대행 운행과 냉동장치 경고가 있었고, 온도 로그에는 그보다 앞선 이탈이 있었다.

시간순으로 놓고 보니 “인계 시점 정상”과 “운송 전 구간 정상”은 다른 주장이었다. 담당 차량·구간, 온도 이력, 실제 통지 기록을 나눠 확인하고 계약의 책임 이전 시점과 대조했다. 정상으로 돌아왔다는 이유만으로 과거 이탈이나 고객 안전 문제를 지우지 않도록 했다.

이 경험은 데이터 해석에도 적용했다. `—`는 미확인이지 피해 없음이 아니고, 조사 기록 부재는 안전 확인 완료가 아니다. 검사한 상단·중단이 정상이라는 사실로 미검사 하단까지 정상이라고 결론 내리지 않았다.

## 사례 2. 광고 문구, 실제 발언, 공식 조건을 분리하기

빠른 배송 배너와 당일배송 불가 안내가 충돌했다. 인플루언서 발언과 공식 무료배송 조건도 달랐다. 단순히 공식 규정만 반복하면 고객이 광고를 믿고 구매한 맥락을 놓치고, 광고를 그대로 따르면 권한 없는 혜택을 약속하게 된다.

따라서 세 질문으로 나눴다.

1. 고객이 본 안내나 발언이 실제로 있었는가?
2. 그 안내가 현재 주문에 적용되는 공식 조건인가?
3. 잘못된 안내라면 누가 정정하고 어떤 경로로 접수해야 하는가?

방송 기록이 있는 경우 발언 자체를 부정하지 않았다. 다만 발언이 있었다는 사실을 새 할인·무료배송을 승인한 것으로 확대하지 않았다. 사과, 현재 적용 가능한 대안, 정정 요청은 별도로 처리하도록 설계했다.

## 사례 3. 예전 처리 경험을 현행 권리로 확대하지 않기

가상 고객에게 과거 차액 보상과 무하자 교환 경험을 확인했다. 당시 실제로 처리됐다는 사실은 의미가 있지만, 지금도 같은 방식으로 처리해야 한다는 근거는 아니었다. 적용 시점, 현행 규정, 과거 약속의 문면·권한·이행 여부를 따로 확인했다.

가격 인하 보상도 고객이 “20% 할인”이라고 말한 표현을 그대로 계산에 쓰지 않았다. 같은 SKU의 실제 구매금액과 현재 정상가를 비교하고, 보상 기간과 지급 수단을 확인했다. 현금 환불이 아닌 보상 쿠폰이 규정이라면 차액 이상이 되는 최소 쿠폰을 선택하도록 했다.

## 사례 4. 안전 확인과 금전 처리를 분리하기

곰팡이 사진이 오면 주문번호부터 반복해서 묻는 흐름은 고객의 우려를 놓친다. 섭취 중단, 먹었는지와 몸 상태 확인이 먼저였다. 반대로 배탈을 주장했다는 이유만으로 상품 하자나 증상과의 인과관계가 확인된 것은 아니었다.

하자 증빙, 환불 선택, 배상 검토를 분리하고, 환불과 동일 로트 안전 확인도 서로 다른 접수로 관리했다. 사진은 현재 대화와 대상 주문에 연결하고 주문이 바뀌면 이전 증빙과 동의를 초기화했다. 첨부 URL이나 고객이 넣은 메타데이터 자체를 “사진 확인 완료”로 인정하지 않았다.

## 사례 5. 온라인 정책을 축제 매대에 적용하지 않기

축제 현장 구매에는 온라인 주문번호가 없었다. 현장 전단에는 온라인과 다른 접수 창구와 증빙 조건이 있었다. 온라인 주문번호를 계속 요구하면 고객은 진행할 수 없고, 온라인 환불 API를 호출해도 대상이 맞지 않는다.

그래서 구매 채널을 정책의 적용 조건으로 남겼다. 축제 문의는 현장·사무소 접수 절차로 안내하고, 그 연락처를 온라인몰 전체 대표 연락처처럼 재사용하지 않았다. 같은 “상한 상품” 문의라도 구매 채널에 따라 다음 행동이 달라졌다.

## 저장과 적용을 따로 확인했다

원본을 저장한 뒤 추출한 지식에는 확인 상태, 출처, 적용 조건, 예외와 공개 범위를 붙였다. 미확인 사항은 삭제하거나 모델이 보충하게 하지 않았다. 운영 엔진에는 확인된 공개 항목만 검색 대상으로 전달했다.

후반에는 두 채팅의 자료가 어긋나지 않도록 통합 전달 파일을 만들었다. 하지만 파일을 만들었다는 보고만으로 봇 반영 완료라고 하지 않았다. 실제 프로세스가 읽은 파일 목록과 SHA256을 비교했다. 마지막 검색 대상은 174레코드였지만, 의미가 겹치는 기록이 있어 공식 지식 발굴량과 동일하게 표시하지 않았다.

## 잘되지 않았던 접근도 있었다

보유하지 않은 자료를 다른 표현으로 다시 요청하거나, 소개가 막힌 관계를 다른 사람을 통해 되묻는 일이 반복됐다. 연락처 9명에서 마지막 한 명을 찾는 데도 시간이 들었다. 자료의 빈칸을 모두 채우려는 시도보다, 질문 전후 발굴률과 실제 상담에 미치는 영향을 함께 봤어야 했다.

최종 확인한 관계자별 발굴률의 단순 평균은 45.8%였다. 이 수치는 자료의 개수와 다르며, 질문별 증가분을 모두 추적한 것도 아니었다. 다음에는 관계자·주제·질문·새 사실·발굴률 변화를 한 표로 관리하고, 두 번 확인 불가인 경로는 명시적으로 종료하겠다.
